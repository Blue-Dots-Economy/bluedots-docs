The vocabulary below is used consistently across the product, this documentation and the code. Definitions are deliberately precise.

## Domain model

<CardGrid>
  <Card title="Blue Dot / Signal">
    A local signal of intent from a citizen or enterprise, around livelihoods and services. Stored as an item.
  </Card>
  <Card title="Network">
    The shared contract that lets independent instances interoperate (e.g. `blue_dot`, `yellow_dot`). Defined by a `network.json` schema.
  </Card>
  <Card title="Domain">
    A role inside a network (e.g. `student`). An instance serves one or more domains via `SERVED_DOMAINS`.
  </Card>
  <Card title="Instance">
    One deployment of the Signals API serving its configured domains.
  </Card>
  <Card title="Item">
    A versioned, schema-typed record. `item_type` is a schema identifier such as `profile_1.0`, never freeform.
  </Card>
  <Card title="Action">
    An interaction between items.
  </Card>
  <Card title="Event">
    The structured result of an action.
  </Card>
  <Card title="Seeker / Provider">
    The demand side and supply side of a signal — e.g. a jobseeker (seeker) and a local employer (provider).
  </Card>
  <Card title="Service Provider">
    An organisation delivering a support service around the job-seeking process — training, counselling, assessment, placement assistance. The third participant type, served by the `service_provider` domain.
  </Card>
  <Card title="Blue Dot Verified">
    The state a profile reaches after a person — the adaptor or the aggregator — reviews and confirms it. The one human-in-the-loop step in the lifecycle.
  </Card>
  <Card title="Assisted route">
    Onboarding where the adaptor or field team brings a participant in on their behalf.
  </Card>
  <Card title="Self route">
    Onboarding where the participant starts the process themselves.
  </Card>
  <Card title="Intake method">
    How data is collected on the assisted route: offline camp, bulk upload, outbound campaign, or inbound QR campaign.
  </Card>
  <Card title="AI Voice Agent">
    The call-based, local-language channel for completing a profile. The primary self-service channel; its prompts are published as DPGs.
  </Card>
  <Card title="Blue Dot Webapp">
    The self-serve web app built on the Signals DPG — the fallback channel for participants who prefer typing to speaking.
  </Card>
  <Card title="MSME (a.k.a. SMB)">
    Micro, small and medium enterprise — the employer side of the livelihoods use case. These docs use **MSME**, matching the Indian statutory term. *SMB* means the same thing and is kept only in the Brown Dots sector naming.
  </Card>
  <Card title="Adaptor (a.k.a. adopter / anchor adopter)">
    The organisation deploying Blue Dots for a district, state or domain. These docs use **adaptor** throughout; *adopter* and *anchor adopter* mean the same role.
  </Card>
</CardGrid>

## Platform

<CardGrid>
  <Card title="Signals DPG">
    The network-aware backend that stores items and matches them across instances.
  </Card>
  <Card title="Aggregator DPG">
    The aggregator-facing application for onboarding participants and bulk-creating their signals.
  </Card>
  <Card title="Aggregator">
    An organisation (institute, employer, NGO, government department) that onboards participants. Scoped by `aggregator_id`, which is never trusted from the client.
  </Card>
  <Card title="Adaptor">
    An organisation deploying and extending the Blue Dots DPGs for a district or domain.
  </Card>
</CardGrid>

## Technical

<CardGrid>
  <Card title="item_type">
    Schema identifier for an item (e.g. `profile_1.0`).
  </Card>
  <Card title="item_instance_url / item_schema_url">
    Backend-generated URLs for an item's location and schema. Never set by clients.
  </Card>
  <Card title="Instance-local fetch">
    `GET /api/v1/item/fetch` — reads "my own items" with a brief cache.
  </Card>
  <Card title="Inter-instance fetch">
    `GET /api/v1/network/item/fetch` — count-first discovery across peers, merged and cached.
  </Card>
  <Card title="Service token">
    A Keycloak client-credentials token used by an integrating DPG to call Signals, sent with an acting-org header. The client id equals the organisation's `slug`.
  </Card>
</CardGrid>
