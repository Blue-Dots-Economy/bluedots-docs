These words mean the same thing in the product, in these docs and in the code.

## Domain model

<CardGrid>
  <Card title="Blue Dots">
    The platform and programme: open-source software that helps people and organisations near each other, in the same district, find each other. It runs several sector networks, each shown as a colour of dot.
  </Card>
  <Card title="Dot (also: signal)">
    A short listing from a person or organisation that says what they need or offer — for example a young person looking for work, or a student looking for a tutor. Stored as an item. *Signal* is the same thing, and the name the software uses.
  </Card>
  <Card title="Network">
    The set of rules for one sector, written in a `network.json` schema: the roles, the forms and the actions. Each colour of dot is a network — Blue Dot (`blue_dot`) for jobs, Yellow Dot for education, and so on. See [the networks today](/core-concepts/networks-domains-instances/#the-networks-today).
  </Card>
  <Card title="Blue Dot, Yellow Dot, …">
    A colour names one network. **Blue Dot** is the jobs network; Yellow Dot is education, Purple Dot is for persons with disabilities, Orange Dot is tourism. The generic word for a listing on any network is "a dot".
  </Card>
  <Card title="Domain">
    A role inside a network — for example `seeker` and `provider` on the jobs network, or `student` on the education network. An instance serves one or more domains via `SERVED_DOMAINS`.
  </Card>
  <Card title="Instance">
    One running copy of the Signals API, serving the domains it is configured for.
  </Card>
  <Card title="Item">
    A versioned, schema-typed record. `item_type` is a schema identifier such as `profile_1.0`, never freeform.
  </Card>
  <Card title="Action">
    An interaction between items.
  </Card>
  <Card title="Event">
    The structured result of an action.
  </Card>
  <Card title="Seeker / Provider">
    The person who needs something and the person or organisation who offers it. On the jobs network: a job seeker and a local employer. On the disability network: a person looking for a device or service, and an organisation that provides it.
  </Card>
  <Card title="Service Provider">
    On the jobs network, an organisation that offers support to job seekers — training, counselling, assessment or placement help. A third role, served by the `service_provider` domain in the deployed pilot schemas (the example schema has only `seeker` and `provider`).
  </Card>
  <Card title="Practitioner">
    On the tourism network, a person or business that lists what they offer: a homestay owner, an artisan, a guide or a performer.
  </Card>
  <Card title="Verified">
    The state a profile reaches after a person from the adaptor or aggregator reviews and confirms it. This is the only step in the lifecycle that a person must do by hand.
  </Card>
  <Card title="Assisted route">
    Onboarding where the adaptor or field team brings a participant in on their behalf.
  </Card>
  <Card title="Self route">
    Onboarding where the participant starts the process themselves.
  </Card>
  <Card title="Intake method">
    How data is collected on the assisted route: offline camp, bulk upload, outbound campaign, or inbound QR campaign.
  </Card>
  <Card title="AI Voice Agent">
    A phone-call channel, in the caller's own language, for completing a profile. It is the main way people sign up by themselves. Its prompts are published as DPGs.
  </Card>
  <Card title="Web app">
    The self-serve web app built on the Signals DPG, for participants who prefer typing to speaking. Each network shows it with its own name and colours.
  </Card>
  <Card title="MSME (a.k.a. SMB)">
    Micro, small and medium enterprise — for example a kirana shop or a wholesaler (the Brown Dot idea, possible), or an employer on the jobs network. These docs use **MSME**, matching the Indian statutory term. *SMB* means the same thing and is kept only in the Brown Dot sector naming.
  </Card>
</CardGrid>

## Platform

<CardGrid>
  <Card title="Signals DPG">
    The network-aware backend that stores items and matches them across instances.
  </Card>
  <Card title="Aggregator DPG">
    The aggregator-facing application for onboarding participants and bulk-creating their signals.
  </Card>
  <Card title="Aggregator">
    A local organisation that signs participants up and checks their details — for example a skilling centre, a school, a disability organisation, a tourism body, a self-help group or a government department. Scoped by `aggregator_id`, which is never trusted from the client.
  </Card>
  <Card title="Coordinator">
    A person who works for an aggregator and onboards participants. Coordinators join an aggregator by invitation only.
  </Card>
  <Card title="Adaptor (also: adopter, anchor adopter)">
    The organisation that deploys and extends Blue Dots for a district, state or sector. These docs use **adaptor**; *adopter* and *anchor adopter* mean the same role.
  </Card>
  <Card title="Brand">
    The name, logo and colours a deployment shows to users. A brand sits on top of a network and does not change its rules. It is set in a `brand.json` next to the network schema.
  </Card>
</CardGrid>

## Technical

<CardGrid>
  <Card title="item_type">
    Schema identifier for an item (e.g. `profile_1.0`).
  </Card>
  <Card title="item_instance_url / item_schema_url">
    Backend-generated URLs for an item's location and schema. Never set by clients.
  </Card>
  <Card title="Instance-local fetch">
    `GET /api/v1/item/fetch` — reads "my own items" with a brief cache.
  </Card>
  <Card title="Inter-instance fetch">
    `GET /api/v1/network/item/fetch` — count-first discovery across peers, merged and cached.
  </Card>
  <Card title="Service token">
    A Keycloak client-credentials token used by an integrating DPG to call Signals, sent with an acting-org header. The client id equals the organisation's `slug`.
  </Card>
</CardGrid>
