These are the records that let people and organisations nearby find each other. Inside an instance, everything is built from three primitives: **items**, **actions** and **events**.

## Item

An **item** is a versioned, schema-typed record, the unit of data in Signals. Examples: a job seeker's `profile_1.0` on the Blue Dot (jobs) network, a `job_posting_1.0`, or a student's `profile_1.0` on the Yellow Dot (education) network.

- `item_type` is always a schema identifier such as `profile_1.0`, **never** freeform text.
- `item_instance_url` and `item_schema_url` are **generated by the backend** at creation time. Clients must not set them.
- Item tables are **partitioned** in the database; queries use partition-aware helpers so the planner can prune efficiently.

## Action

An **action** is an interaction *between items*. Each network lists its own actions in `network.json`:

| Network | Action | Example |
|---|---|---|
| Blue Dot (jobs) | `apply` | A job seeker applies to an employer's job posting. |
| Blue Dot (jobs) | `connect` | An employer invites a job seeker to an interview, or contacts another employer. |
| Yellow Dot (education) | `connect` | A student asks a tutor for help, or a tutor offers to help a student. |
| Purple Dot (persons with disabilities) | `connect` | A person with a disability and a service provider ask to connect. Either side can start. |
| Orange Dot (tourism) | None | Listings are public. Visitors call the number shown, so no action is recorded. |

## Event

An **event** is the *structured result* of an action: a stored, machine-readable record such as "this student sent a connect request to this tutor at time T, and it was accepted". Analytics and impact measurement read events.

## How they relate

![An action connects one item to another, for example a seeker to a provider, and produces an event: the structured result that is stored. The action is apply on the jobs network and connect on the education network. Some networks, such as tourism, have no actions because listings are public.](../../../assets/diagrams/items-actions-events.png)

From listing to result, in these terms:

1. Create **items** for both sides, for example a student and a tutor.
2. The network discovers compatible items.
3. An **action** connects two items.
4. An **event** records the outcome. Events are used to improve matching and to measure results in each district.

For how items are read locally vs. across the network, and how they are written, see [Read & Write Paths](/core-concepts/technical/read-write-paths/). For the full term list, see the [Glossary](/core-concepts/glossary/).
